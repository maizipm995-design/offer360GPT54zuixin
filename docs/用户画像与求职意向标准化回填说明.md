# 用户画像与求职意向标准化回填说明

## 文档说明

本文件用于说明回填脚本的执行方式和回填规则；如果需要查看本轮跨环境执行留痕，请同时参考：

- `docs/用户画像标准化跨环境回填执行记录.md`
- `docs/旧canonical到新canonical映射表.md`

## 一、适用范围

本脚本用于把历史库中仍保留旧长 canonical 或旧 alias 写法的用户数据，按当前词典口径回填为新的短 canonical。

本次回填范围仅包含：

- `user_profiles.degree`
- `user_profiles.major`
- `user_job_preference_tags.intentionCity`
- `user_job_preference_tags.intentionJob`
- `user_job_preference_tags.intentionCompany`

**不会修改**：

- 招聘公告原文字段
- 词典表本身
- 会员、订单、投递等业务数据

## 二、脚本位置

- 脚本：`apps/api/prisma/backfill-user-normalization.ts`
- 共享工具：`apps/api/prisma/normalization-storage.ts`

## 三、执行命令

### 1. 先做 dry-run

```bash
npm run db:backfill:user-normalization
```

作用：

- 只统计会变化的用户资料与求职意向
- 输出前 5 条样例
- **不落库**

### 2. 正式写回数据库

```bash
npm run db:backfill:user-normalization -- --apply
```

### 3. 仅回填指定用户

```bash
npm run db:backfill:user-normalization -- --apply --userId=用户ID1,用户ID2
```

适用于：

- 小范围验证
- 线上单用户纠偏
- 分批灰度执行

## 四、回填规则

### 1. 单值字段

- `degree`
- `major`

处理规则：

- 命中当前启用词典时，写回对应 canonical
- 未命中词典时，保留原值
- 空字符串统一收口为 `null`

### 2. 数组字段

- `intentionCity`
- `intentionJob`
- `intentionCompany`

处理规则：

- 对每个值逐项按当前启用词典归一
- 命中词典时写回 canonical
- 未命中词典时保留原值
- 自动去重并保留原有顺序

## 五、推荐缓存与注意事项

当前推荐缓存与标准化缓存都存在 **API 进程内内存** 中。

因此正式回填后必须执行以下任一动作：

- **重启 API 进程**
- 或在维护窗口内执行回填后再拉起 API

否则会出现：

- 数据库已回填
- 但运行中进程仍继续使用旧缓存

## 六、建议执行顺序

1. 先执行 dry-run，确认样例符合预期
2. 先用 `--userId=` 做 1 到 3 个用户的小范围回填
3. 核对前台个人中心、后台用户页、专属推荐结果是否一致
4. 再执行全量 `--apply`
5. 回填完成后重启 API

## 七、建议核验点

- **个人资料**：`全日制本科` 是否回到 `本科`
- **专业**：`计算机科学与技术` 是否回到 `计算机`
- **意向岗位**：`软件开发工程师` 是否回到 `开发`
- **意向岗位**：`行政助理` 是否回到 `人事 / 行政`
- **意向公司**：`烟草` / `国网` / `腾讯控股` 是否回到对应 canonical
- **前后台一致性**：个人中心与后台用户页应看到相同口径的数据

## 八、输出说明

脚本会输出：

- 当前执行模式：`dry-run` 或 `apply`
- 发生变化的画像记录数
- 发生变化的求职意向记录数
- 前 5 条样例变更

如果正式写回成功，日志中还会额外提示：

- 需要重启 API，刷新进程内缓存
