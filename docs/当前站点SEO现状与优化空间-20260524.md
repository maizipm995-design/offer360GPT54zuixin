# 当前站点 SEO 现状与优化空间

## 1. 盘点范围

- 盘点对象：`https://www.offer360.cn`
- 对照维度：代码实现现状 + 线上实际输出 + 可继续优化空间
- 盘点时间：`2026-05-24`

## 2. 当前站点已经具备的 SEO 方案

### 2.1 全局 SEO 基建已基本成型

当前公开站点已经不是“完全没做 SEO”的状态，基础层已经搭起来了，主要包括：

- 全局 Metadata 已统一封装在 `apps/web/lib/seo.ts`
- 根布局 `apps/web/app/layout.tsx` 已挂载全站根级 metadata
- 已配置 `metadataBase`、默认 `title`、`description`、`keywords`
- 已配置 `canonical`、Open Graph、Twitter Card
- 已配置百度站长验证 `baidu-site-verification`
- 已配置 `manifest.ts`
- 已配置 `robots.ts`
- 已配置 `sitemap.ts`

这说明当前站点已经完成了 SEO 基建一期的大部分工作，不再是“页面裸奔”的状态。

### 2.2 公开核心页与站点功能页已有页面级 SEO 配置

以下页面已经通过 `buildPageMetadata()` 做了页面级 TDK 或页面级收录边界配置：

- 首页 `/`
- 服务列表页 `/services`
- 服务详情页 `/services/[id]`
- 会员页 `/membership`
- 求职之路页 `/career-journey`
- 简历AI优化页 `/resume-optimizer`
- 面试逐字稿页 `/interview-transcript`

其中：

- 首页已输出独立 `title`、`description`、`canonical`
- 服务详情页已基于真实服务数据生成 metadata
- 服务详情页缺失服务数据时会自动 `noindex`
- 简历AI优化页与面试逐字稿页虽然当前不参与公开索引，但也已经具备独立页面级 metadata 与明确的 `noindex` 边界

这部分说明当前 SEO 已经从“只有全局标题”升级到了“核心落地页分页面表达主题”。

### 2.3 Structured Data 已有基础覆盖

当前代码里已经存在并落地了以下结构化数据：

- `Organization`
- `WebSite`
- `WebPage / CollectionPage / AboutPage`
- `ItemList`
- `BreadcrumbList`
- `Service`

当前实际使用情况：

- 首页注入了 `Organization` + `WebSite` + `CollectionPage`
- 服务列表页注入了 `CollectionPage` + `ItemList`
- 服务详情页注入了 `WebPage` + `Service` + `BreadcrumbList`
- 会员页与求职之路页已补充对应 `WebPage` 结构化数据

这对搜索引擎理解站点品牌、站点类型、服务页层级是加分项。

### 2.4 收录边界已经开始治理

当前非公开页并不是“默认允许收录”，而是已经做了明显边界控制：

- `/login` 为 `noindex`
- `/register` 为 `noindex`
- `/personal-center` 为 `noindex,nofollow`
- `/invite/[randomKey]` 为 `noindex,nofollow`
- `/resume-optimizer` 为 `noindex,nofollow`
- `/checkout` 通过 `head.tsx` 输出 `noindex,nofollow`
- `/payments/wechat/callback` 通过 `head.tsx` 输出 `noindex,nofollow`
- `robots.ts` 也明确屏蔽了后台、接口、支付、个人中心、邀请、简历优化等路径

这说明当前站点已经在做“公开页可收录，功能页不污染索引”的治理，而不是全站放开。

### 2.5 首页权重收口方向是正确的

代码中 `/jobs` 已永久跳转到 `/`，同时全站导航和 Logo 返回首页都已经指向 `/`。  
这说明首页身份在代码层已经基本收口到根路径，而不是继续把 `/jobs` 当主首页。

这是一个正确方向，因为主域名首页权重不再被旧路径分散。

## 3. 线上实测结论

本次对线上正式域名做了直接检查，结论分成“已生效”和“存在明显问题”两部分。

### 3.1 已在线上生效的部分

线上首页 HTML 已能直接看到以下信号：

- 正常输出首页 `title`
- 正常输出首页 `description`
- 正常输出 `canonical=https://www.offer360.cn`
- 正常输出 `og:title`、`og:description`、`og:url`
- 正常输出 `twitter:card`
- 正常返回 `manifest.webmanifest`
- 首页最终 URL 为 `https://www.offer360.cn/`，未发生 `/ -> /jobs` 跳转

说明首页主 SEO 信号大部分已经真实生效，不只是停留在代码里。

### 3.2 当前线上最明显的问题

#### 问题 1：`robots.txt` 和 `sitemap.xml` 线上暴露了错误 Host

线上实测结果显示：

- `https://www.offer360.cn/robots.txt` 中的 `Host` 是 `http://localhost:14000`
- 同一个 `robots.txt` 中的 `Sitemap` 也是 `http://localhost:14000/sitemap.xml`
- `https://www.offer360.cn/sitemap.xml` 中的 `<loc>` 也使用了 `http://localhost:14000`

这属于当前最严重的 SEO 技术问题之一。

它会直接导致：

- 搜索引擎收到错误的站点主域名信号
- sitemap 里的 URL 不是正式可抓取地址
- 抓取入口和 canonical 域名信号发生冲突
- 首页虽然 canonical 正确，但 sitemap/robots 在“反向拉低”一致性

这类问题优先级应定为 `P0`。

#### 问题 2：线上 sitemap 只有静态页，没有服务详情页

当前线上 `sitemap.xml` 仅包含：

- `/`
- `/services`
- `/membership`
- `/career-journey`

但代码里本来设计了把 `services/[id]` 动态加入 sitemap。  
线上缺失说明当前动态服务 URL 没有真正进入搜索引擎发现入口。

这会导致：

- 服务详情页被发现速度更慢
- 高商业意图页面的抓取效率下降
- 服务详情页更依赖站内内链，而不是主动被 sitemap 推送

这类问题优先级建议定为 `P0-P1`。

#### 问题 3：首页内容价值受实时数据影响较大

线上首页实测时，岗位统计和列表均显示为 `0`。  
如果这不是临时数据状态，而是长期现象，那么会带来两个风险：

- 搜索引擎对页面内容质量和更新价值判断偏弱
- 用户点击进入后，页面满足搜索意图的能力下降

SEO 不是只看标签，页面本身是否“有货”同样影响收录与排名。

这类问题属于 `内容质量/转化质量` 风险，优先级建议定为 `P1`。

## 4. 当前 SEO 方案可以如何定性

如果用一句话概括当前站点的 SEO 现状：

**当前已经具备“现有页面 SEO 基建方案”，但还没有进入“流量增长型 SEO”阶段。**

更准确地说，当前方案已经覆盖了：

- Metadata 基建
- canonical 基建
- OG/Twitter 基建
- robots/sitemap/manifest 基建
- 公开页与私有页收录边界
- 首页与服务页的基础 structured data

但当前仍然受限于：

- 公开可索引页面总量有限
- 缺少更多高价值内容型落地页
- 线上部署环境对 SEO 配置的一致性仍有缺口

所以，当前方案应定义为：

`现有页面范围内的 SEO 技术治理 + 基础收录优化`

而不是：

`已经具备大规模自然流量增长能力的 SEO 体系`

## 5. 还有哪些优化空间

下面按优先级整理。

### 5.1 P0：必须优先修复

#### 1. 修复线上 `robots.txt` / `sitemap.xml` 的域名错误

目标：

- 所有站点地图 URL 必须统一为 `https://www.offer360.cn`
- `robots.txt` 中的 `Host` 和 `Sitemap` 必须指向正式域名

建议动作：

- 检查线上 `WEB_APP_BASE_URL`
- 检查生成 metadata route 时读取到的环境变量是否与页面渲染一致
- 修复后重新验证：
  - `https://www.offer360.cn/robots.txt`
  - `https://www.offer360.cn/sitemap.xml`

这是当前 SEO 技术层最先要修的点。

#### 2. 让服务详情页真正进入 sitemap

目标：

- 把 `/services/[id]` 全量加入正式 sitemap

建议动作：

- 排查 `sitemap.ts` 中 `serverGet('/service-products')` 为什么线上失败或未生效
- 修复后验证 sitemap 中是否出现所有服务详情 URL

因为当前最接近“高意图转化落地页”的页面，就是服务详情页。

#### 3. 做上线后的 SEO 验收清单

当前问题说明：代码正确不代表线上最终输出正确。  
建议把以下检查加入发布后固定验收：

- 首页 `title/description/canonical`
- `robots.txt` 域名是否正确
- `sitemap.xml` 域名是否正确
- sitemap 是否包含服务详情页
- 关键公开页 `noindex/index` 是否符合预期

这可以避免“代码已修，但线上 SEO 信号仍错误”的情况再次出现。

### 5.2 P1：很值得继续优化

#### 4. 升级 OG 图片资源

当前 OG 图片实际使用的是品牌 Logo 小图地址，不是标准分享封面。

优化建议：

- 改成独立的 `1200x630` 品牌分享图
- 尽量使用自有稳定静态资源域名，而不是第三方图床
- 首页、服务页可按需拆分不同封面

原因：

- 当前虽然字段齐全，但素材质量偏弱
- 社交分享点击率和品牌展示一致性仍有提升空间

#### 5. 扩展 Structured Data 的信息量

当前 structured data 已有基础，但仍偏轻量。

可继续增强：

- `WebSite` 增加 `SearchAction`（前提是站内搜索希望被强调）
- `Organization` 增加更多品牌信息
- 服务列表页补 `ItemList`
- 会员页补更贴合业务的 schema

这不是最急，但会提升搜索引擎对页面类型的理解深度。

#### 6. 强化页面首屏语义表达

当前首页、服务页、会员页、求职之路页已经有基础 metadata，但仍可以继续强化首屏内容的搜索意图表达：

- 首页首屏更明确强化“这是中国校招招聘信息汇总平台中的权威入口”，并同时覆盖“校招招聘信息 / 简历AI优化 / 面试辅导 / 笔试真题 / 面试逐字稿 / 求职全流程服务”语义
- 服务列表页继续强化服务分类、适用人群，以及“求职全流程服务矩阵”的表达
- 会员页进一步强化权益、适合人群、使用场景，以及与岗位搜索、资料包、面试逐字稿等能力的关联
- 求职之路页强化内容层级、标题结构、内容摘要，并与简历、笔试、面试等关键环节形成完整成长路径表达

这类优化属于“页面内容语义增强”，对排名和点击转化都有效。

#### 7. 明确首页与服务页之间的内链策略

当前已有导航和服务入口，但站内内链仍可以更有策略：

- 首页核心区域更多指向 `/services`
- 服务列表页与会员页、求职之路页之间建立更明确的主题关联
- 服务详情页增加返回服务列表与相关服务推荐

这有助于：

- 提升搜索引擎爬行深度
- 提升高价值页面获得的内部权重

### 5.3 P2：属于后续增长空间

#### 8. 增加更多可承接搜索意图的公开页面

这是长期最大的增长空间，但不一定是当前版本要做的。

如果未来放开页面扩展，真正能拉开自然流量上限的通常不是再补几个 meta，而是新增页面资产，例如：

- 岗位详情页
- 企业专题页
- 届别聚合页
- 城市聚合页
- 行业聚合页
- 求职攻略内容页

当前站点如果一直只保留少量公开页，那么 SEO 上限会天然受限。

## 7. 最终结论

### 当前 SEO 方案是什么样

当前站点已经具备一套比较完整的 **SEO 基建方案**：

- 有全局 metadata
- 有页面级 TDK
- 有 canonical
- 有 OG/Twitter
- 有 `robots.ts`
- 有 `sitemap.ts`
- 有 `manifest.ts`
- 有 structured data
- 有公开页/私有页收录边界治理

所以结论不是“没做 SEO”，而是：

**已经做到了技术 SEO 的基础版，而且整体方向正确。**

### 还有哪些核心优化空间

最关键的不是再补几个 meta，而是优先解决这 3 件事：

1. 修复线上 `robots/sitemap` 域名错误
2. 让服务详情页真正进入 sitemap
3. 建立上线后的 SEO 验收机制

在这之后，再继续做：

- OG 图片升级
- structured data 增强
- 页面首屏语义增强
- 站内内链优化

### 一句话判断

**当前站点 SEO 已有“基建”，但线上配置一致性还有明显缺口；先修正式域名与 sitemap 问题，再做页面语义和内容资产增强，才是当前最合理的优化路径。**
