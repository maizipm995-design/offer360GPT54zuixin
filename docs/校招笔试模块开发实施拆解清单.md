# 校招笔试模块开发实施拆解清单

## 1. 文档定位

本文档是在《校招笔试模块整体开发方案》基础上的研发执行版拆解文档，目标是把“整体方案”进一步细化为可直接排期、建表、定义接口、拆页面、拆组件、开发联调和验收的实施清单。

本文档只解决以下七类内容：

1. Prisma 数据表与迁移清单
2. API 接口契约
3. 后台页面拆分
4. 前端页面与组件拆分
5. 简答题自动判分实现方案
6. OSS 转存落地流程
7. 按开发顺序的任务清单

默认前提：

1. 首版即包含完整刷题与判分能力。
2. 首版同步建设一级分类与二级分类后台管理。
3. 首版统一完成图片转存 OSS。
4. 首版包含简答题自动判分。

## 2. 交付边界

## 3. Prisma 数据表与迁移清单

## 3.1 数据表总览

本模块建议新增以下 Prisma Model：

1. `CampusExamCategory`
2. `CampusExamSpecial`
3. `CampusExamQuestion`
4. `CampusExamImportBatch`
5. `CampusExamImportError`
6. `CampusExamPracticeSession`
7. `CampusExamPracticeAnswer`
8. `CampusExamWrongQuestion`
9. `CampusExamFavorite`
10. `CampusExamNote`
11. `CampusExamSubjectiveJudgement`

其中主表之间关系如下：

1. 一级分类 `1 -> n` 二级分类
2. 二级分类 `1 -> n` 题目
3. 二级分类 `1 -> n` 导入批次
4. 练习会话 `1 -> n` 答题明细
5. 题目 `1 -> n` 用户答题明细
6. 主观题答题明细 `1 -> 1/n` 主观题判分记录

## 3.3 Prisma 关系与索引要点

必须建立的唯一约束与索引：

1. 一级分类 `slug` 唯一
2. 用户错题表 `userId + questionId` 唯一
3. 用户收藏表 `userId + questionId` 唯一
4. 用户答题明细表 `sessionId + questionId` 唯一
5. 二级分类表 `categoryId + sortOrder` 索引
6. 题目表 `specialId + status + createdAt` 索引
7. 题目表 `questionType + difficulty` 索引
8. 批次错误表 `batchId + rowNo` 索引
9. 主观题判分表 `answerId` 索引
10. 主观题判分表 `questionId + createdAt` 索引

## 4. API 接口契约

## 4.1 统一约定

统一接口约定如下：

1. 后台接口走 `/admin/campus-exam/*`
2. 用户侧接口走 `/campus-exam/*`
3. 统一返回项目现有响应包装结构
4. 列表接口统一支持分页、关键字、状态筛选
5. 枚举值由后端统一返回，前端不写死映射

## 4.2 后台接口契约

### 4.2.1 一级分类接口

#### `POST /admin/campus-exam/categories`

用途：

1. 新建一级分类

请求体：

```json
{
  "name": "政治理论",
  "slug": "politics",
  "description": "政治理论相关题库",
  "sortOrder": 10,
  "status": "active"
}
```

返回核心字段：

```json
{
  "id": "uuid",
  "name": "政治理论",
  "slug": "politics",
  "status": "active"
}
```

#### `GET /admin/campus-exam/categories`

用途：

1. 获取一级分类列表
2. 支持状态筛选

查询参数：

1. `keyword`
2. `status`
3. `page`
4. `pageSize`

#### `PATCH /admin/campus-exam/categories/:id`

用途：

1. 编辑一级分类

### 4.2.2 二级分类接口

#### `POST /admin/campus-exam/specials`

请求体：

```json
{
  "id": 26,
  "categoryId": "uuid",
  "name": "马克思主义",
  "description": "专项描述",
  "sortOrder": 10,
  "status": "active"
}
```

关键校验：

1. `id` 必须与 Excel `分类专项id` 对齐
2. 不允许重复创建
3. 只能挂到一个一级分类下

#### `GET /admin/campus-exam/specials`

用途：

1. 获取二级分类列表
2. 支持按一级分类筛选

查询参数：

1. `categoryId`
2. `keyword`
3. `status`
4. `page`
5. `pageSize`

#### `GET /admin/campus-exam/specials/:specialId`

用途：

1. 获取二级分类详情
2. 展示题量、导入批次、最近操作信息

#### `PATCH /admin/campus-exam/specials/:specialId`

用途：

1. 编辑二级分类

### 4.2.3 导入接口

#### `POST /admin/campus-exam/specials/:specialId/import/preview`

用途：

1. 上传 Excel
2. 执行表头校验、字段标准化、分类校验、图片预校验
3. 不正式落库

请求方式：

1. `multipart/form-data`
2. 文件字段名建议为 `file`

响应字段建议：

```json
{
  "batchId": "uuid",
  "specialId": 26,
  "fileName": "校招题库.xlsx",
  "totalCount": 120,
  "successCount": 116,
  "failCount": 4,
  "summary": {
    "headerErrors": 0,
    "categoryMismatch": 2,
    "imageValidationErrors": 1,
    "answerFormatErrors": 1
  },
  "errors": [
    {
      "rowNo": 9,
      "fieldName": "分类专项id",
      "errorCode": "CATEGORY_SPECIAL_MISMATCH",
      "errorMessage": "当前上传上下文为 26，Excel 行值为 28"
    }
  ]
}
```

#### `POST /admin/campus-exam/specials/:specialId/import/confirm`

用途：

1. 基于预览批次正式导入
2. 下载图片并转存 OSS
3. 写入题目与错误记录

请求体建议：

```json
{
  "batchId": "uuid",
  "overwritePolicy": "skip_existing"
}
```

枚举建议：

1. `skip_existing`
2. `replace_existing`
3. `fail_on_duplicate`

#### `GET /admin/campus-exam/import-batches`

用途：

1. 查询导入批次列表

#### `GET /admin/campus-exam/import-batches/:batchId`

用途：

1. 查询批次详情

#### `GET /admin/campus-exam/import-batches/:batchId/errors`

#### `POST /admin/campus-exam/import-batches/:batchId/retry-assets`

## 7. 简答题自动判分实现方案

## 7.1 判分目标

首版简答题自动判分要求不是“像人工老师一样百分百精确”，而是做到：

1. 稳定
2. 可解释
3. 可回溯
4. 可逐步优化

## 7.2 判分链路

建议采用四步链路：

1. 参考答案标准化
2. 用户答案标准化
3. 规则判分
4. AI 评分兜底与复核

## 7.3 参考答案标准化

对 `answerJson` 中的简答题答案做预处理：

1. 去 HTML 标签
2. 去多余空格
3. 分句
4. 提炼核心关键词
5. 提炼可替换同义词
6. 标记否定表达
7. 生成评分规则快照

建议为简答题扩展内部规则结构：

```json
{
  "type": "essay",
  "values": ["财政政策通过扩大财政支出刺激总需求"],
  "ruleConfig": {
    "keywords": ["财政政策", "扩大财政支出", "总需求"],
    "synonyms": {
      "扩大财政支出": ["增加财政支出", "扩大政府支出"]
    },
    "mustHit": ["财政政策"],
    "scoreWeights": {
      "财政政策": 0.3,
      "扩大财政支出": 0.4,
      "总需求": 0.3
    }
  }
}
```

说明：

1. 首版允许 `ruleConfig` 在导入后由后台维护补充。
2. 若 Excel 暂无显式规则字段，可先根据参考答案自动生成初版规则。

## 7.4 用户答案标准化

规则：

1. 去除首尾空白
2. 标点统一
3. 中英文括号统一
4. 数字全半角统一
5. 大小写统一
6. 常见停用词弱化
7. 长文本按句拆分

## 7.5 规则判分算法

建议规则判分输出：

1. `matchedKeywords`
2. `missingKeywords`
3. `mustHitSatisfied`
4. `rawScore`
5. `normalizedScore`
6. `judgementResult`

判分步骤：

1. 判断必命中项是否满足
2. 统计关键词命中率
3. 按权重计算基础分
4. 判断是否存在语义相反表达
5. 生成解释文本

结果映射建议：

| 分数区间 | 结果 |
| --- | --- |
| `>= 0.85` | `correct` |
| `0.45 - 0.84` | `partial` |
| `< 0.45` | `wrong` |

## 7.6 AI 评分兜底

触发场景建议：

1. 规则分在边界区间，例如 `0.40 - 0.60`
2. 答案表达开放，关键词难以覆盖
3. 题目被后台标记为“语义判分优先”

AI 输入应严格结构化，包含：

1. 题目
2. 参考答案
3. 评分规则摘要
4. 用户答案
5. 输出 JSON schema

AI 输出建议：

```json
{
  "score": 0.72,
  "result": "partial",
  "matchedPoints": ["描述了扩大财政支出的方向"],
  "missingPoints": ["未提及逆周期调节目标"],
  "reason": "方向正确，但论述不完整"
}
```

AI 评分约束：

1. 不能直接替代规则判分
2. 必须输出结构化字段
3. 必须落库 `aiReasoning`
4. 低置信度时转 `pending_review`

## 7.7 主观题评分服务拆分

建议后端拆成：

1. `CampusExamSubjectiveRuleService`
2. `CampusExamSubjectiveAiService`

职责：

1. 规则服务只负责关键词与规则分

## 8. OSS 转存落地流程

## 8.1 目标

题目图片、解析图片、HTML 内嵌图片必须从源外链转存到 OSS，确保：

1. 资源稳定
2. 不依赖外部第三方站点持续可用
3. 前端渲染地址可控
4. 可追踪失败原因

## 8.2 资源处理链路

建议链路：

1. Excel 解析
2. 提取全部图片 URL
3. URL 格式校验
4. 临时下载
5. MIME 与大小校验
6. 上传 OSS
7. 回写题目字段与 HTML 中的图片地址
8. 记录转存结果

## 8.3 OSS 路径规划

建议路径格式：

1. `campus-exam/questions/{questionId}/stem/main-{timestamp}.jpg`
2. `campus-exam/questions/{questionId}/analysis/main-{timestamp}.jpg`
3. `campus-exam/questions/{questionId}/inline/stem-{index}-{timestamp}.png`
4. `campus-exam/questions/{questionId}/inline/analysis-{index}-{timestamp}.png`

## 8.4 转存状态建议

建议在 `inlineAssetJson` 或临时对象中维护：

```json
[
  {
    "sourceUrl": "https://example.com/a.jpg",
    "assetType": "stem_inline",
    "status": "success",
    "ossUrl": "https://oss.example.com/...",
    "contentType": "image/jpeg",
    "size": 123456
  }
]
```

状态枚举建议：

1. `pending`
2. `downloading`
3. `uploading`
4. `success`
5. `failed`

## 8.5 失败处理策略

失败原因常见包括：

1. URL 无法访问
2. 下载超时
3. 返回非图片 MIME
4. 图片过大
5. OSS 上传失败

处理策略：

1. 预览阶段记录警告
2. 正式导入阶段默认要求转存成功
3. 失败资源写入批次错误明细
4. 后台支持重试转存

## 8.6 后端服务拆分

建议拆分：

1. `CampusExamAssetExtractorService`
2. `CampusExamAssetDownloaderService`
3. `CampusExamAssetTransferService`
4. `CampusExamAssetRewriteService`

## 8.7 前端资源使用规则

渲染优先级：

1. 优先 `questionImageOssUrl`
2. 次选 `analysisImageOssUrl`
3. 内嵌图片使用改写后的 HTML OSS 地址
4. 无可用地址时展示占位
