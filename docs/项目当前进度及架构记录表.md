## 二、项目一句话概况

`offer360` 是一个以**校招岗位聚合 + 求职服务变现 + 会员权益 + 邀请分销 + 后台运营管理**为主线的全栈项目，采用 `Next.js 14 + NestJS + Prisma + MySQL` 的 Monorepo 结构，当前已经完成用户侧主流程与后台管理基础功能，并补齐了后台兑换码与批量导入导出能力。

### 4.3 前后端调用链

#### 4.3.1 用户侧调用链
1. 用户访问 `apps/web/app/*` 页面；
2. SSR 页面通过 `serverGet` 直连 API，客户端交互通过 `clientFetch` 请求 `/api/proxy/*`；
3. `apps/web/app/api/proxy/[...path]/route.ts` 负责把请求代理到 Nest API；
4. `apps/api` 控制器进入对应业务模块；
5. 业务模块通过 `PrismaService` 访问 MySQL；
6. 统一响应拦截器返回标准响应体。

#### 4.3.2 后台调用链
1. 管理员从 ` /admin/login ` 登录；
2. 后端签发管理员 JWT；
3. 前端保存 `ADMIN_TOKEN_COOKIE`；
4. 后台页面请求统一走前端代理；
5. 代理把管理员 Token 透传到 ` /admin/* ` 接口；
6. 后端通过 `AdminJwtAuthGuard + AdminPermissionGuard` 完成身份与权限校验；
7. 业务模块返回后台列表、表单、批量工具、兑换码数据。

- `users`：用户账号主表；

- `commission_config`：分销比例配置；
- `inv_redirect_link` / `inv_visitor_trace` / `inv_bind_log`：邀请链路支撑表。

#### 4.4.2 后台主数据
- `admin_users`：管理员账号；
- `admin_roles`：角色；

### 4.5 核心业务流程

#### 4.5.1 岗位浏览与投递
用户登录 → 进入 ` /jobs ` → 搜索 / 筛选 / 推荐 → 查看公告 → 投递 / 复制邮箱 → 更新求职进度 → 会员用户查看内推信息。

#### 4.5.2 求职服务转化
用户进入 ` /services ` → 查看商品详情 → 创建订单 → 订单置为已支付 → 商品销量增加 → 若存在上级邀请关系则生成分销流水与钱包入账。

#### 4.5.3 会员开通与兑换码
用户进入 ` /membership ` → 查看权益内容 → 直接开通会员或输入兑换码 → 后端更新会员表 / 兑换码表 / 使用日志 → 前端刷新剩余天数。

#### 4.5.4 邀请分享与增长
用户在个人中心查看邀请码和分享文案 → 分享中转链接 → 被邀请用户注册后理论上绑定上级关系 → 达成里程碑后发放会员奖励与可提现收益展示。

#### 4.5.5 后台运营流程
管理员登录 → 按权限查看菜单 → 管理岗位 / 用户 / 会员 / 商品 / 订单 / 分销 / 兑换码 → 支撑运营、客服、财务的日常操作。

1. **先做后台角色 / 管理员管理 + 操作日志**，把后台体系从“可用”提升为“可治理”；
2. **再补订单退款与分销扣回闭环**，解决后台财务侧操作缺口；
3. **同步补齐注册 / 邀请落地链路与后台运营动作**，让增长与运营闭环真正可跑通；
4. **最后再处理手机验证码、支付接口、Redis / Elasticsearch / OSS 等增强项**，避免过早分散主线开发精力。
