# 简历优化 V1 - Puppeteer 一致性治理技术方案

## 一、方案结论（最终建议口径）

- **技术路线**：`前端 React 实时预览 + 服务端 Puppeteer 导出 PDF`。
- **一致性原则**：前端预览与服务端导出**不维护两套模板**，而是共用同一份 `ResumeDocument` 文档组件、同一套样式源、同一套 A4 尺寸规则。
- **预览口径**：编辑页中间预览区不是“另做一个相似页面”，而是**A4 打印页的缩放显示**。
- **导出口径**：服务端 `Puppeteer` 不直接抓编辑器页面，而是打开独立的 `print route`，该路由只渲染纯简历文档。
- **字体口径**：V1 **不开放字体切换**，先固定站内默认字体；前端预览与服务端 Chromium 必须使用同一字体资源，禁止跟随各设备 OS 默认字体。
- **尺寸口径**：文档纸张、页边距、标题间距等全部按打印场景设计，统一使用 `mm / pt` 等稳定单位，禁止用响应式网页布局替代打印布局。
- **导出时机**：用户编辑时只做前端即时渲染；只有在“下载 PDF”或“一键适配确认”时，才调用服务端进行最终打印校验与 PDF 生成。
- **一致性目标**：不追求数学意义上的 `100%` 零偏差，但要做到**肉眼接近所见即所得**，并将差异收敛在极少数边界场景（如超长文案、分页临界值、外链图片异常）内。

## 二、V1 产品边界（已拍板）

### 2.1 范围包含

- 网站导航栏新增 `简历优化` 入口；
- 必须登录后才能使用；
- 普通用户 `FREE_USER` 与标准会员 `STANDARD_MEMBER` 最多创建 `1` 份简历；
- 超级会员 `SUPER_MEMBER` 最多创建 `5` 份简历；
- V1 只做 `1` 套模板；
- 提供结构化表单编辑、模块管理、A4 预览、自动保存、一键适配、PDF 导出；
- 导出格式仅支持 `PDF`。

### 2.2 范围不包含

- 多模板体系；
- AI 文案优化；
- 导出图片 / Word；
- 多份导出历史；
- 分享链接；
- 诊断评分。

## 三、当前核心问题与治理目标

### 3.1 核心问题

若直接采用“前端预览一套样式、服务端导出另一套样式”模式，极易出现以下偏差：

- 同样内容在前端预览为 `1` 页，导出后变成 `2` 页；
- 浏览器中刚好一行显示完，导出 PDF 时因为字体宽度变化发生换行；
- 预览区的对齐、间距、模块高度与导出结果不一致；
- 用户看到的页面与最终下载 PDF 差异明显，降低产品信任感。

### 3.2 治理目标

本方案的核心治理目标不是“强行维护两套渲染结果一致”，而是：

1. **从架构上尽量让两端渲染同源**；
2. **把影响一致性的变量收口到最少**；
3. **让导出结果成为最终标准答案**；
4. **在编辑态保持 300ms ~ 500ms 内的即时反馈体验**。

## 四、一致性治理总原则

### 4.1 单一文档源（Single Source of Truth）

必须抽离一份纯展示型文档组件，例如：

- `ResumeDocument`

该组件只负责：

- 接收简历数据；
- 渲染头部信息、教育背景、实习经历、项目经验、技能等模块；
- 应用主题色、字号、行距、页边距等样式；
- 输出稳定的 A4 文档结构。

该组件**不负责**：

- 表单编辑；
- 自动保存；
- API 请求；
- 弹窗；
- 拖拽；
- 按钮交互；
- 权限判断。

### 4.2 预览与导出共用同一模板

- 编辑器页面中的中部预览，直接渲染 `ResumeDocument`；
- 服务端 `Puppeteer` 打开的打印页，也直接渲染 `ResumeDocument`；
- 不允许单独维护“预览模板”和“导出模板”两份 JSX/HTML。

### 4.3 前端预览只是打印页缩放显示

前端预览的本质应为：

- 内部保持真实 A4 比例；
- 外层按屏幕空间做缩放展示；
- 禁止为了适配屏幕宽度而改动内部排版逻辑。

### 4.4 导出结果为最终标准结果

- 编辑过程中的预览是高保真参考；
- 最终下载的 PDF 是正式结果；
- 一键适配、是否溢出、是否单页成功等最终判定，以服务端 Chromium 打印校验结果为准。

## 五、总体架构设计

### 5.1 页面/路由划分

建议新增以下页面：

1. **编辑页**：`/resume-optimizer`
   - 左侧：模块编辑表单；
   - 顶部：排版控制条；
   - 中部：A4 实时预览。

2. **打印页**：`/resume-optimizer/print/[resumeId]`
   - 只渲染纯文档内容；
   - 不出现按钮、表单、浮层、拖拽把手等编辑器 UI；
   - 用于 `Puppeteer` 导出与服务端校验。

### 5.2 前后端职责边界

#### 前端职责

- 表单输入与模块管理；
- 本地实时预览；
- 本地快速溢出预估；
- 防抖自动保存；
- 发起下载/校验请求。

#### 后端职责

- 简历草稿持久化；
- 创建份数限制校验；
- 获取打印页数据；
- 启动 `Puppeteer` 打开打印页；
- 等待页面 ready；
- 执行最终高度校验与 PDF 导出。

## 六、前端一致性方案

### 6.1 文档组件拆分建议

建议组件层级如下：

- `ResumeEditorPage`
- `ResumeToolbar`
- `ResumeSidebarEditor`
- `ResumePreviewCanvas`
- `ResumeDocument`
- `ResumeSectionHeader`
- `ResumeHeaderBlock`
- `EducationSection`
- `InternshipSection`
- `ProjectSection`
- `SkillSection`
- 其他可选模块组件

其中真正决定导出结果的一层是：

- `ResumeDocument`
- 其内部的各模块纯展示组件

### 6.2 A4 预览容器规范

- 内层文档固定为 `210mm × 297mm`；
- 外层允许使用 `transform: scale(...)` 或等比缩放容器进行显示；
- 编辑区只控制缩放，不改动文档内部布局。

### 6.3 样式源统一

建议将文档样式独立成：

- `resume-document.css`
- `resume-print.css`

规则如下：

- `resume-document.css`：承载绝大多数共享文档样式；
- `resume-print.css`：只放打印页特有的极少量样式（如去除屏幕阴影、控制打印背景保留、隐藏非文档元素）；
- 编辑页与打印页都引用 `resume-document.css`。

### 6.4 禁止的布局写法

为了降低一致性风险，文档区域内应尽量避免：

- 依赖浏览器窗口宽度变化的响应式重排；
- 预览端与导出端使用不同的字号换算规则；
- 由 hover / focus / active 状态触发布局变化；
- 依赖 `100vw`、`100vh`、动态百分比撑开内容；
- 把编辑器侧边栏宽度直接影响到文档正文宽度。

## 七、字体与资源治理

### 7.1 V1 字体策略

V1 不开放字体切换功能，统一固定一套站内默认字体。

原因：

- 字体宽度和字高是影响换行、分页和单页适配的最大变量；
- 如果前端预览和服务端导出字体不一致，哪怕字号相同，也会导致版面差异。

### 7.2 服务端字体要求

- 运行 `Puppeteer` 的服务端环境必须安装与前端一致的默认字体；
- 前端和打印页 CSS 中均显式指定同一字体族；
- 不允许直接依赖“系统默认字体”或浏览器默认回退字体作为正式口径。

### 7.3 图片与图标策略

- V1 尽量减少非必要图片；
- 若有头像/作品二维码等内容，必须在导出前确认资源加载完成；
- 图标优先使用 `SVG` / 内联资源，不建议依赖不稳定的第三方外链。

## 八、打印页与 Puppeteer 导出治理

### 8.1 打印页原则

打印页必须满足：

- 单独路由；
- 单独布局；
- 只渲染文档；
- 使用相同数据结构和相同文档组件；
- 不受编辑器界面状态影响。

### 8.2 页面 ready 协议

导出前必须等待打印页进入“稳定可导出”状态，建议建立显式协议：

- 所有数据加载完成；
- `document.fonts.ready` 完成；
- 所有必要图片加载完成；
- 页面高度稳定；
- 前端向页面注入 ready 标记，例如：`window.__RESUME_PRINT_READY__ = true`。

`Puppeteer` 侧只有在检测到 ready 后，才允许执行：

- 溢出校验；
- PDF 导出。

### 8.3 Puppeteer 导出建议

- 统一使用 Chromium；
- 统一使用固定 viewport 和打印配置；
- 开启背景色保留；
- 显式设置 `A4` 纸张；
- 关闭不必要动画；
- 浏览器实例尽量复用，避免每次冷启动。

## 九、单页适配与溢出治理

### 9.1 编辑态快速预估

前端编辑过程中：

- 用户输入后 `300ms ~ 500ms` 防抖刷新预览；
- 可在本地基于预览容器高度做快速溢出预估；
- 若疑似超页，先展示轻提示，但**不在每次输入时调用服务端**。

### 9.2 一键适配流程

用户点击“一键适配”后：

1. 前端按既定规则逐步微调：
   - 字号；
   - 行距；
   - 段间距；
   - 页边距；
2. 本地预览即时反馈；
3. 用户确认或点击导出时，服务端再用 `Puppeteer` 做最终校验；
4. 若仍溢出，则停止压缩并返回明确提示。

### 9.3 服务端最终校验职责

服务端最终校验用于：

- 判断实际打印页是否超出单页；
- 返回精确的 overflow 状态；
- 作为最终导出前的真值判定。

## 十、接口建议

### 10.1 简历草稿接口

建议新增：

- `POST /resume-drafts`：创建简历；
- `GET /resume-drafts/:id`：获取详情；
- `PATCH /resume-drafts/:id`：更新草稿；
- `GET /resume-drafts`：获取当前用户简历列表；
- `DELETE /resume-drafts/:id`：删除简历。

### 10.2 校验与导出接口

建议新增：

- `POST /resume-drafts/:id/validate-layout`
  - 用于触发服务端最终单页校验；
- `POST /resume-drafts/:id/export-pdf`
  - 用于生成并下载 PDF。

### 10.3 数据返回建议

`validate-layout` 建议至少返回：

- `isOverflow`：是否超页；
- `pageCount`：实际页数；
- `overflowHeight`：超出高度（可选）；
- `hintMessage`：提示文案（如建议精简模块）。

## 十一、数据模型建议（V1）

建议新增核心表：`resume_drafts`

建议字段：

- `id`
- `userId`
- `title`
- `templateCode`
- `contentJson`
- `styleJson`
- `layoutJson`
- `status`
- `createdAt`
- `updatedAt`

说明：

- `contentJson`：保存结构化模块数据；
- `styleJson`：保存主题色、字号、行距、页边距、标题样式等；
- `layoutJson`：保存模块顺序、显示/隐藏状态等；
- V1 建议采用 `JSON` 存储，便于快速迭代。

## 十二、验收标准

### 12.1 一致性验收

以下场景应人工逐项对比前端预览与最终 PDF：

- 基础简历（内容较少）；
- 刚好单页满版的临界简历；
- 含多段实习 / 项目经历的长简历；
- 含头像 / 链接 / 奖项的复合简历；
- 主题色、字号、行距、页边距被修改后的简历。

验收通过标准建议为：

- 模块顺序一致；
- 主要文本换行差异不可明显感知；
- 页数一致；
- 标题、边距、颜色、间距肉眼基本一致；
- 未出现导出缺字、重叠、异常分页。

### 12.2 性能验收

- 编辑预览响应：`300ms ~ 500ms` 内可见更新；
- 自动保存：停止输入 `1s` 后触发；
- PDF 导出：目标控制在 `3s` 左右；
- 超时或失败要有明确提示。

## 十三、已知风险与规避策略

### 13.1 字体差异风险

- **风险**：字体不同导致换行和分页变化；
- **规避**：固定站内默认字体并在服务端安装同款字体。

### 13.2 浏览器差异风险

- **风险**：用户本地浏览器预览与 Chromium 导出内核不完全一致；
- **规避**：前端联调和验收以 Chromium 系浏览器为主，降低跨内核偏差。

### 13.3 资源未加载完成风险

- **风险**：字体/图片尚未 ready 就导出；
- **规避**：建立页面 ready 协议，`Puppeteer` 等待 ready 后再导出。

### 13.4 双模板漂移风险

- **风险**：后续开发中无意间复制出第二份模板；
- **规避**：强制预览页和打印页复用 `ResumeDocument`，禁止复制文档 JSX。

## 十四、推荐开发顺序

### 第一阶段：底座搭建

- 建 `resume_drafts` 数据模型；
- 新增 `ResumeModule` 与基础 CRUD；
- 搭建编辑页、打印页路由骨架；
- 搭建 `ResumeDocument` 纯展示组件。

### 第二阶段：一致性底座

- 固定 A4 文档尺寸；
- 抽离共享样式；
- 固定默认字体；
- 完成预览缩放与打印页共用模板。

### 第三阶段：导出链路

- 接入 `Puppeteer`；
- 完成 print route 加载与 ready 协议；
- 完成 PDF 导出；
- 完成服务端最终溢出校验。

### 第四阶段：体验闭环

- 接入自动保存；
- 接入一键适配；
- 接入溢出提示；
- 补齐异常处理与验收清单。

## 十五、最终建议

对于当前 `简历优化 V1`，推荐采用：

- **前端即时预览**：保障编辑体验；
- **服务端 Puppeteer 导出**：保障正式文档质量；
- **同模板 + 同样式 + 同字体 + 同 A4 规则**：作为一致性治理的唯一主线。

只要坚持这条主线，`Puppeteer` 并不会天然导致“前端预览和最终 PDF 完全两张皮”；相反，在简历这种对打印质量和文档标准要求较高的场景下，它更适合作为最终导出标准链路。
