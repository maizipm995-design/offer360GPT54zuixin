# Offer360 自动化部署改造手册

## 改造结果
- 保留现有 Docker 容器化架构，不推翻现有前后端与数据库项目结构。
- 开发环境与生产环境彻底隔离：
  - 本地使用根目录 `docker-compose.dev.yml`
  - 生产使用 `deploy/prod/docker-compose.prod.yml`
- 生产环境改造成 `蓝绿双槽位 + 共享基础设施`：
  - `mysql` / `redis` / `elasticsearch` / `gateway` 为共享稳定层
  - `web/api/wechat-pay-gateway` 分为 `blue` 和 `green` 两个发布槽位
- 发布流程改造成：
  - 本地改代码
  - 本地 Docker 联调通过
  - 推送 Git 仓库
  - CI 构建并推送镜像
  - CI 远程执行服务器发布脚本
  - 服务器自动迁移数据库、拉起新槽位、健康检查、切换网关
- 回滚流程改造成：
  - 默认回切到上一稳定槽位
  - 无需手动登录服务器逐个停容器

## 目录说明
- `apps/api/Dockerfile`：后端统一多阶段构建，同时支持开发态和生产态
- `apps/web/Dockerfile`：前端统一多阶段构建，生产态输出 Next standalone
- `apps/wechat-pay-gateway/Dockerfile`：支付网关生产镜像
- `docker-compose.dev.yml`：本地开发专用，带源码挂载与热更新
- `deploy/prod/docker-compose.prod.yml`：生产发布专用，带蓝绿槽位与共享基础设施
- `deploy/prod/scripts/install-server.sh`：服务器初始化脚本，只需执行一次
- `deploy/prod/scripts/deploy-release.sh`：CI 调用的正式发布脚本
- `deploy/prod/scripts/rollback-release.sh`：CI 或人工触发的回滚脚本
- `deploy/prod/scripts/migrate.sh`：仅执行数据库生产迁移
- `deploy/prod/scripts/status.sh`：查看当前蓝绿槽位和镜像状态
- `.github/workflows/deploy.yml`：自动化流水线配置
- `docs/生产环境参数与CI-Secrets清单.md`：生产参数归属、`.env` 使用说明与 CI Secrets 清单

## 一次性服务器初始化
### 1. 准备服务器
- 安装 Docker Engine 与 Docker Compose Plugin
- 确保服务器 `80` 端口可用，后续由 `gateway` 容器接管
- 准备一个部署目录，例如 `/opt/offer360`
- 把仓库中的 `deploy/prod` 内容上传到该目录，或者在服务器上先拉一份仓库

### 2. 初始化生产配置
- 复制环境模板：

```bash
cp .env.example .env
```

- 按实际环境填写 `.env`
- 把微信支付证书放到 `WECHAT_PAY_CERTS_HOST_PATH` 指向的目录

### 3. 初始化运行时目录和基础设施
- 在服务器执行：

```bash
cd /opt/offer360/deploy/prod
ENV_FILE=/opt/offer360/.env bash scripts/install-server.sh
```

- 该步骤会完成：
  - 创建运行时状态文件
  - 创建 Nginx 当前激活 upstream 文件
  - 启动 `mysql` / `redis` / `elasticsearch` / `gateway`

## GitHub Actions 流水线说明
当前交付的是 `GitHub Actions + 国内 OCI 镜像仓库` 方案；如果你后续迁到 Gitee，只需要复用同一套服务器脚本、环境变量与镜像仓库策略，把流水线触发层替换掉即可。

### 参数安全边界
- `.env` 只保留开发态占位或测试值，禁止继续写入真实生产密钥
- 服务器 `.env` 保存真实生产业务参数
- CI Secrets 只保存镜像仓库与服务器登录凭据
- 详细字段归属请直接参考 `docs/生产环境参数与CI-Secrets清单.md`

### 需要配置的仓库 Secrets
- `OCI_REGISTRY`：OCI 镜像仓库地址，例如 `registry.cn-hangzhou.aliyuncs.com`
- `OCI_NAMESPACE`：镜像命名空间，例如 `your-namespace`
- `OCI_USERNAME`：镜像仓库账号
- `OCI_PASSWORD`：镜像仓库密码或 AccessToken
- `DEPLOY_HOST`：服务器 IP 或域名
- `DEPLOY_PORT`：服务器 SSH 端口
- `DEPLOY_USER`：服务器登录用户
- `DEPLOY_SSH_KEY`：CI 登录服务器用的私钥
- `DEPLOY_ROOT`：服务器部署目录，例如 `/opt/offer360`

### 触发规则
- 推送到 `main` 或 `master`：自动构建、推送、部署
- 手动触发 `workflow_dispatch`：
  - `action=deploy`：手动部署当前提交
  - `action=rollback`：执行回滚

## 日常开发流程
### 本地启动完整开发环境
```bash
cp .env.example .env
npm run dev:up
```

### 本地开发体验
- `api` / `web` 使用源码挂载，修改后自动热更新
- `shared-builder` 持续 watch `packages/shared`，共享包改动会持续重新编译
- MySQL / Redis / Elasticsearch 使用独立数据卷，与生产环境完全隔离

### 查看地址
- Web：`http://localhost:13000`
- API：`http://localhost:14000/api`
- Swagger：`http://localhost:14000/api/docs`

### 开发结束
```bash
npm run dev:down
```

## 正式发布流程
### 自动发布链路
1. 本地开发完成并验证通过
2. 提交代码到 Git 主干
3. GitHub Actions 构建三个镜像：
   - `offer360-api`
   - `offer360-web`
   - `offer360-wechat-pay-gateway`
4. 镜像推送到 OCI 仓库
5. CI 通过 SSH 将 `deploy/prod` 发布包同步到服务器
6. 服务器执行 `deploy-release.sh`
7. 发布脚本自动完成：
   - 启动共享基础设施
   - 运行 Prisma 生产迁移
   - 在空闲槽位拉起新版本
   - 执行 API / Web 健康检查
   - 重写网关 upstream 并热重载 Nginx
   - 更新当前激活槽位状态

### 生产发布命令
CI 最终执行的核心命令如下：

```bash
cd /opt/offer360/deploy/prod
ENV_FILE=/opt/offer360/.env APP_IMAGE_TAG=<镜像标签> bash scripts/deploy-release.sh
```

## 回滚流程
### 自动回滚
- 在 GitHub Actions 中手动触发：
  - `action=rollback`
  - `rollback_slot=auto`

### 指定槽位回滚
```bash
cd /opt/offer360/deploy/prod
ENV_FILE=/opt/offer360/.env ROLLBACK_SLOT=blue bash scripts/rollback-release.sh
```

### 回滚原理
- 永远保留一个“上一稳定槽位”
- 网关只切换流量，不会删除数据库卷
- 当前回滚为应用层回切，不自动执行数据库降级

## 数据安全说明
- MySQL 使用命名卷持久化，容器删掉后数据不会丢
- 发布只更新镜像和应用容器，不覆盖业务数据卷
- 数据库结构变更由 Prisma migration 管理，禁止发布时直接全量覆盖数据库
- 回滚只切应用版本，不会回滚业务数据

## 服务解耦说明
- 前端、后端、支付网关镜像独立构建
- 构建阶段已经解耦，可单独复用缓存
- 部署阶段默认一起发布同一版本标签
- 如需后续只发前端或只发后端，可以继续扩展流水线，仅替换单个镜像标签

## 常用运维命令
### 查看生产栈状态
```bash
docker compose --env-file /opt/offer360/.env -f /opt/offer360/deploy/prod/docker-compose.prod.yml ps
```

### 查看当前激活槽位
```bash
cat /opt/offer360/deploy/prod/runtime/release-state.env
```

### 查看发布状态
```bash
cd /opt/offer360/deploy/prod
ENV_FILE=/opt/offer360/.env bash scripts/status.sh
```

### 查看网关当前指向
```bash
cat /opt/offer360/deploy/prod/runtime/nginx/active-upstream.conf
```

### 查看应用日志
```bash
docker compose --env-file /opt/offer360/.env -f /opt/offer360/deploy/prod/docker-compose.prod.yml logs -f web-blue api-blue
```

## 注意事项
- 首次切换到容器化网关前，请先停掉原宿主机 Nginx 或释放 `80` 端口
- 生产回滚默认只保证“应用层快速回切”，数据库迁移必须遵循向后兼容策略
- 如果需要 HTTPS，推荐在云负载均衡或外层网关统一终止 TLS；当前交付默认以 HTTP 80 为入口
