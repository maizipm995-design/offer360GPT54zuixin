# SEO优化文件级执行清单
> 版本：v1.0  
> 日期：2026-06-02  
> 适用范围：Offer360 现有已上线页面 SEO 优化执行方案  
> 约束前提：禁止新增任何页面、禁止新增任何路由、禁止改动网站整体架构；所有优化动作仅在现有页面与现有组件内落地。

---

## 一、执行目标

本方案用于指导现有站点的 SEO 收录优化落地，重点解决以下问题：

1. 大量非首页导航直达的深层内页入口层级较深，搜索引擎发现与收录效率偏低。
2. 部分存量页面 TDK 偏通用，实体词覆盖不足，导致长尾词匹配能力弱。
3. 部分页面虽有 SEO 价值，但浏览限制偏重，爬虫无法充分获取正文内容。
4. 站内内链与结构化数据已有基础，但仍需围绕深层页继续补强。

---

## 二、执行边界

### 1. 明确允许的动作

- 优化现有页面的标题、关键词、描述、canonical、结构化数据。
- 在现有页面中增加静态说明区、FAQ 区、相关推荐区、返回上级页入口、相关栏目入口。
- 对现有页面中的浏览权限进行收敛优化，仅放开“公开浏览”能力。
- 调整 `robots`、`sitemap`、页面 metadata、现有组件文案与现有内链结构。

### 2. 明确禁止的动作

- 新增任何页面。
- 新增任何路由。
- 调整网站主导航层级结构。
- 通过新建专题页、聚合页、着陆页来做 SEO。
- 放开会导致用户数据泄露、付费能力失守、会员能力失效的写操作权限。

### 3. 权限调整总原则

- 可读内容：按需放开公开预览。
- 可执行动作：继续保留登录、会员、下单、下载、提交等拦截。
- 核心目标：让搜索引擎能抓正文，但不能越权执行站内操作。

---

## 三、优先级建议

### P0：必须优先执行

- `sitemap`、`robots`、全站默认 metadata 信号校正
- `笔试真题` 分类页 / 专项页 / 题目详情页 SEO 强化
- `求职服务` 详情页 SEO 强化
- `AI简历优化`、`面试辅导` 页面公开浏览能力优化

### P1：建议紧随执行

- 核心页面正文补强
- 深层页内部推荐与返回链路补强
- 结构化数据精细化

### P2：后续增强

- 基于真实更新时间的 `lastModified`
- 多来源内容更新时间透出
- 搜索引擎提交与巡检流程

## 五、基础层执行清单

### 1. `apps/web/lib/seo.ts`

- 改什么：
  - 统一全站默认 `title`、`description`、`keywords`、`topics` 词池。
  - 按“名企校招 / 笔试真题 / AI简历优化 / 面试辅导 / 求职服务”重新校正站点主题。
  - 补齐站点级 `WebSite`、`Organization`、`SiteNavigationElement` 结构化数据。
  - 预留核心页面的统一 SEO 工具方法，避免后续页面口径漂移。
- 为什么：
  - 这是全站 SEO 统一口径的根文件，所有页面后续优化都应共享同一套主题词与结构化信号。
- 风险点：
  - 若主题词堆砌过多，可能导致 description 和 keywords 可读性下降。
  - 若栏目命名不统一，会造成页面间关键词分散。
- 验收方式：
  - 检查核心页面输出的 title、description、canonical 是否统一口径。
  - 检查页面源码中是否存在 `WebSite`、`Organization`、`SiteNavigationElement` schema。

### 2. `apps/web/app/layout.tsx`

- 改什么：
  - 在现有全局布局中注入站点级结构化数据。
  - 保持不新增页面，仅增强全站共用 SEO 信号。
- 为什么：
  - 全局布局是最稳定的站点信号注入点，适合承载站点级 schema。
- 风险点：
  - 重复注入相同 schema 可能导致结构化数据冗余。
- 验收方式：
  - 打开任意公开页面查看 HTML 源码，确认结构化数据存在且不重复堆叠。

### 3. `apps/web/app/robots.ts`

- 改什么：
  - 保持登录、支付、后台、个人中心等低 SEO 价值页面继续限制抓取。
  - 明确允许 `AI简历优化`、`面试辅导`、`笔试真题`、`求职服务`、相关公开深层页被抓取。
  - 补齐现有可抓取深层路由的 allow 口径。
- 为什么：
  - `robots` 是抓取边界的总开关，必须先明确“哪些页面值得收录、哪些页面必须屏蔽”。
- 风险点：
  - 放开范围过大可能导致账户页、支付页、参数页被误抓。
- 验收方式：
  - 访问 `robots.txt`，确认仅核心公开页可抓，账户/交易/后台页仍被限制。

### 4. `apps/web/app/sitemap.ts`

- 改什么：
  - 在不新增页面的前提下，尽可能完整纳入现有公开可收录页面。
  - 优先覆盖：首页、求职服务、会员页、笔试真题首页、分类页、专项页、服务详情页、AI简历优化、面试辅导。
  - 条件允许时，进一步补充题目详情页。
  - 后续将统一 `lastModified` 替换为真实内容更新时间。
- 为什么：
  - 站点地图直接影响深层页被搜索引擎发现的效率。
- 风险点：
  - 若直接纳入大量内容质量不足或访问不稳定的页面，可能拉低整体抓取质量。
  - 若 `lastModified` 全部使用当前时间，搜索引擎对内容时效判断会失真。
- 验收方式：
  - 访问 `sitemap.xml`，确认核心静态页与深层页已被纳入。
  - 抽查 URL 是否均为现有公开页面，无登录态依赖。

## 六、核心栏目页执行清单

### 5. `apps/web/components/layout/site-navigation.tsx`

- 改什么：
  - 统一导航文案命名，确保导航关键词与页面 SEO 口径一致。
  - 不调整导航结构，只校正文案与可访问性属性。
- 为什么：
  - 导航是全站最强的站内锚文本来源之一，必须与核心关键词统一。
- 风险点：
  - 若导航名称与页面 H1/TDK 不一致，会削弱栏目主题稳定性。
- 验收方式：
  - 页面顶部导航、移动端导航、页面标题口径一致。

### 6. `apps/web/app/(site)/page.tsx`

- 改什么：
  - 优化首页 TDK，使其作为站点总入口承接五大核心栏目关键词。
  - 强化首页到各核心栏目、核心深层页的站内内链。
  - 在现有页面中补充栏目说明区与相关入口，不新增页面。
- 为什么：
  - 首页是站内权重最高的页面，负责把抓取与权重分发到其他核心页。
- 风险点：
  - 若首页内链过多、过杂，可能稀释主导航意图。
- 验收方式：
  - 首页源码中可见五大核心栏目入口与相关说明文本。
  - 从首页无需登录即可访问所有目标核心页。

### 7. `apps/web/app/(site)/services/page.tsx`

- 改什么：
  - 强化“求职服务”页的栏目级 TDK。
  - 在当前页面中增加与 `名企校招 / 笔试真题 / AI简历优化 / 面试辅导` 的互链说明。
  - 优化服务列表页中的锚文本与摘要文案。
- 为什么：
  - 列表页是服务详情页的主要传权入口，必须具备更强的栏目聚合作用。
- 风险点：
  - 若列表页摘要过于营销化，可能弱化信息页属性。
- 验收方式：
  - 服务列表页 title/description 更聚焦求职服务场景。
  - 页面中存在清晰的服务相关说明与相关栏目互链。

### 8. `apps/web/app/(site)/membership/page.tsx`

- 改什么：
  - 将会员页从“权益销售页”补强为“会员权益说明页 + 相关功能入口页”。
  - 增加到 `AI简历优化 / 面试辅导 / 求职服务 / 笔试真题` 的说明性内链。
- 为什么：
  - 会员页虽不一定是核心收录页，但可作为多个功能页之间的辅助权重分发节点。
- 风险点：
  - 不可让会员页承载过多与主业务无关的 SEO 文本。
- 验收方式：
  - 会员页对相关能力有说明性文本与栏目入口，不影响原购买链路。

### 9. `apps/web/app/(site)/resume-optimizer/page.tsx`

- 改什么：
  - 在现有页面中补充静态说明内容：适用人群、优化能力、使用流程、FAQ、与求职流程的关系。
  - 放开公开浏览，保留编辑、保存、导出、AI 调用等动作拦截。
  - 统一输出当前页面 metadata、breadcrumb、结构化数据。
- 为什么：
  - 工具页如果只有交互，没有可抓正文，收录能力很弱。
- 风险点：
  - 若权限放开过度，可能影响原本的登录态业务边界。
- 验收方式：
  - 未登录用户和爬虫能正常访问并看到主要页面内容。
  - 触发写操作时仍有登录拦截。

### 10. `apps/web/app/(site)/interview-transcript/page.tsx`

- 改什么：
  - 将该页作为“面试辅导”落地页补强静态说明内容：适合人群、逐字稿复盘价值、使用流程、FAQ。
  - 放开页面公开浏览，保留提交生成、下载等动作拦截。
  - 补充 breadcrumb 与结构化数据。
- 为什么：
  - 当前该页面对 SEO 的价值主要来自“辅导说明内容”，而非工具本身。
- 风险点：
  - 若仍然保留过强的浏览限制，会导致爬虫只能获取极少内容。
- 验收方式：
  - 未登录可查看主要正文。
  - 提交、下载、会员相关动作仍保持保护。

### 11. `apps/web/app/(site)/career-journey/page.tsx`

- 改什么：
  - 保持现有页面不新增新内容模块结构的前提下，补强与五大核心栏目之间的说明性跳转。
  - 将该页作为辅助内容页承接“校招攻略”“求职路径”等内容词。
- 为什么：
  - 该页天然适合作为“内容支持页”，可帮助核心功能页形成主题闭环。
- 风险点：
  - 不应把该页改造成独立 SEO 专题页。
- 验收方式：
  - 页面与核心栏目之间存在自然内链，且不破坏现有阅读体验。

## 七、深层页执行清单

### 12. `apps/web/app/(site)/services/[id]/page.tsx`

- 改什么：
  - 按服务名称输出更精准的 title、description、keywords。
  - 结合现有服务详情数据强化 schema、breadcrumb、服务说明语义。
  - 在当前详情页中增加“相关服务 / 相关栏目”内链。
- 为什么：
  - 服务详情页是典型深层页，最适合承接高意图搜索词。
- 风险点：
  - 若服务描述与详情数据不统一，可能造成页面口径冲突。
- 验收方式：
  - 抽查多个详情页源码，title 与 description 均带服务实体词。
  - 页面存在返回服务列表与相关栏目入口。

### 13. `apps/web/app/(site)/campus-exam/page.tsx`

- 改什么：
  - 作为“笔试真题”栏目首页，增加栏目说明、题库结构说明、分类入口强化与 SEO 内链区。
  - 在现有页面中增加对分类页、专项页的文本化引导，不新增页面。
- 为什么：
  - 该页面是整个题库体系的总入口，承担深层页分发职责。
- 风险点：
  - 如果只保留卡片入口而没有文本解释，搜索引擎理解页面结构仍然有限。
- 验收方式：
  - 页面中可见分类、专项、练习体系说明文本。
  - 页面能够向分类页和专项页传递稳定 HTML 内链。

### 14. `apps/web/app/(site)/campus-exam/category/[categorySlug]/head.tsx`

- 改什么：
  - 由通用分类模板，升级为尽量带分类实体词的 TDK 方案。
  - 若后续可服务端取数，则进一步输出真实分类名。
- 为什么：
  - 分类页是重要的栏目聚合页，应具备更强的独立收录能力。
- 风险点：
  - 如果仍完全使用通用标题，不利于长尾分类词覆盖。
- 验收方式：
  - 页面 title、description 与分类页主题高度相关。

### 15. `apps/web/app/(site)/campus-exam/category/[categorySlug]/page.tsx`

- 改什么：
  - 在现有页面中增加分类说明、适用方向、题库结构、专项说明、返回栏目入口。
  - 强化分类页到专项页的锚文本和文案语义。
- 为什么：
  - 分类页当前更偏列表容器，正文说明不足。
- 风险点：
  - 页面若仍以纯按钮和列表为主，收录质量不稳定。
- 验收方式：
  - 分类页源码中有稳定正文文本，不依赖用户交互才出现。
  - 专项入口有清晰文案，不只是一句“查看详情”。

### 16. `apps/web/app/(site)/campus-exam/special/[specialId]/head.tsx`

- 改什么：
  - 由通用专项模板，升级为尽量带专项实体词、题量、练习意图的 metadata。
- 为什么：
  - 专项页通常比分类页更接近用户搜索意图。
- 风险点：
  - 标题若过短或过泛，专项页无法获得独立搜索匹配优势。
- 验收方式：
  - 专项页 title/description 中包含专项场景、真题练习意图。

### 17. `apps/web/app/(site)/campus-exam/special/[specialId]/page.tsx`

- 改什么：
  - 在现有页中补充专项介绍、题型分布说明、难度说明、练习建议、返回分类链路。
  - 增加与题目详情页之间的语义衔接说明。
- 为什么：
  - 专项页是典型的高意图深层页，内容越完整，越有独立收录价值。
- 风险点：
  - 不可只强调“开始练习”按钮，而缺少足够正文。
- 验收方式：
  - 页面中有明确的专项介绍说明，不登录也可读。
  - 页面能回链分类页，并引导至题目详情页相关链路。

### 18. `apps/web/app/(site)/campus-exam/question/[questionId]/head.tsx`

- 改什么：
  - 强化题目详情页 title/description，尽可能包含题型、专项、解析、答案等语义。
  - 条件允许时输出题目实体化 metadata。
- 为什么：
  - 题目详情页是最具长尾流量潜力的深层页。
- 风险点：
  - 若仍然使用完全通用标题，题目页即使被抓也难以获得搜索曝光。
- 验收方式：
  - 题目页 metadata 明显区别于分类页、专项页。

### 19. `apps/web/app/(site)/campus-exam/question/[questionId]/page.tsx`

- 改什么：
  - 在现有页面中补充题目所属分类、专项、题型、难度、解析说明、相关返回链路。
  - 强化到专项页、分类页、相关题库入口的内链。
  - 保证正文内容无需登录即可查看。
- 为什么：
  - 题目详情页是深层 SEO 价值最高、也是当前最容易收录不足的页面。
- 风险点：
  - 若题目正文需要依赖客户端异步或登录态才能完整展示，抓取效果仍然有限。
- 验收方式：
  - 未登录状态可查看题目正文、答案解析、所属关系说明。
  - 页面中至少存在返回专项页和分类页的可抓取链接。

## 八、组件与内容承载层执行清单

### 20. `apps/web/components/common/seo-link-cluster.tsx`

- 改什么：
  - 作为现有可复用互链组件，统一承载栏目间互链、栏目摘要、相关推荐入口。
  - 后续按页面场景微调文案，不新增结构。
- 为什么：
  - 能降低多页面重复开发成本，并保证站内互链口径一致。
- 风险点：
  - 若组件文案过于模板化，容易形成重复内容。
- 验收方式：
  - 各接入页面展示的互链文案与当前页主题匹配，不是生硬复制。

### 21. `apps/web/components/resume/resume-editor-page-client.tsx`

  - 配合 `AI简历优化` 页面公开浏览策略，进一步区分“浏览行为”与“写操作行为”。
  - 所有 SEO 可见文本必须在未登录时可正常展示。
- 为什么：
  - 页面真正影响收录的是可见静态内容，而不是编辑功能本身。
- 风险点：
  - 游客拦截边界若控制不准，容易重新影响收录。
- 验收方式：
  - 未登录访问页面时，可看到完整浏览内容；编辑/导出/AI 操作仍受限。

### 22. `apps/web/components/interview/interview-transcript-page-client.tsx`

- 改什么：

  - 保持生成、下载、次数扣减等交互受保护。
- 为什么：
  - 页面正文可见性决定抓取结果，工具交互保护决定业务安全。
- 风险点：
  - 如果主要说明文案被弹窗、登录前置逻辑遮挡，爬虫抓不到有效内容。
- 验收方式：
  - 未登录状态仍可读主要介绍、说明、流程、FAQ 区域。

## 九、不建议放开的页面

以下页面不建议为了 SEO 而放开：

- `apps/web/app/(site)/checkout/*`
- `apps/web/app/(site)/payments/*`
- `apps/web/app/(site)/personal-center/*`
- `apps/web/app/(site)/login/*`
- `apps/web/app/(site)/register/*`
- `apps/web/app/(site)/invite/*`
- `apps/web/app/admin/*`

原因：

- 低内容价值
- 高账户/交易风险
- 收录收益低于安全风险

验收方式：

- 上述页面继续维持 `noindex` 或抓取限制，不纳入公开 SEO 收录优化目标。

## 十、统一验收清单

所有优化完成后，统一按以下标准验收：

1. 未新增任何页面、路由、菜单层级。
2. 目标页面均基于现有页面落地，不破坏站点整体架构。
3. 核心页面与深层页具备独立 TDK。
4. 深层页在站内至少存在稳定可抓取 HTML 入口。
5. 公开可收录页面在未登录状态下可查看主要正文内容。
6. 编辑、提交、下载、购买、会员权益相关动作仍然受保护。
7. `robots.txt` 不误伤目标页。
8. `sitemap.xml` 覆盖核心公开页面与有价值深层页。
9. 页面源码存在对应 canonical、结构化数据与栏目互链。
10. `npm run lint:web` 通过，且 `npm run dev:apps:rebuild` 后页面可正常打开预览。

## 十二、结论

本执行清单可直接用于研发排期与实施，特点如下：

- 不新增页面
- 不改变站点整体架构
- 只在现有页面中做 SEO 补强
- 以深层页收录提升为主要目标
- 以“公开浏览放开、写操作继续保护”为权限调整原则

如需进入开发执行阶段，建议按“第一轮 -> 第二轮 -> 第三轮”推进，先做基础层与核心高收益页，再进入深层题库页细化优化。
