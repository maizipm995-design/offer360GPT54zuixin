## 二、运营配置原则

- **`exact`**：只参与查词归一，不进入搜索与推荐文本召回。适用于高歧义短词，如 `行政`、`会计`、`金融`、`移动`。
- **`contains`**：除归一外，还会进入搜索与推荐文本召回。只建议给稳定长词或明确品牌名使用，如 `Web前端开发`、`中国联合网络通信`、`大学本科`、`计算机科学与技术`。
- **优先顺序**：先保证标准词正确，再补 alias；高频但歧义大的 alias 宁可先放 `exact`，不要直接放开 `contains`。

## 三、运营验收样例

### 1. 高歧义 alias 收口

- 输入：`行政`
- 预期：写库时归一到 `人事 / 行政`
- 预期：普通搜索 / 专属推荐 **不应** 因岗位文本只出现“综合行政”“行政方向”就大面积命中

### 2. 企业 alias 命中提升

- 输入：`中烟`
- 预期：归一到 `中国烟草`
- 预期：普通搜索 / 专属推荐可命中 `山东中烟`、`江苏中烟`、`上海烟草集团` 等公告

### 3. 岗位与学历 alias 命中提升

- 输入：`Web前端开发 + 大学本科`
- 预期：归一到 `前端 + 本科`
- 预期：可命中 `前端开发工程师`、`Web前端`、`大学本科及以上` 等岗位文本

### 4. 地点父级关系联动

- 输入：`深` 或 `深圳市`
- 预期：归一到 `深圳`
- 预期：地点筛选与推荐地点命中均按 `深圳 -> 广东` 口径联动，不误扩到其他广东城市

## 四、建议回归清单

- **写库**：用户意向公司 / 岗位 / 学历 / 专业保存后，数据库应落标准词
- **搜索**：`/jobs` 关键词搜索、地点筛选、学历筛选应体现 alias 提升后的命中变化
- **推荐**：`/jobs` 专属推荐应保持命中提升，同时避免高歧义 alias 造成裸词泛召回
- **后台**：词典中心下载模板、导出全量、导入回写、错误提示都应正常可用
