# 云服务器多站点部署与宝塔 Nginx 交接说明

## 1. 文档目的

本文档记录当前生产云服务器的真实落地状态，供后续独立运维、扩站、排障和交接使用。

当前服务器已经按以下原则完成部署：

- 宝塔面板作为统一运维入口
- 宝塔自带 Nginx 作为全局入口
- Docker 项目只监听宿主机本地端口
- 外网 80/443 全部先进入宝塔 Nginx，再反向代理到容器
- 普通文件夹站点后续仍可与 Docker 站点共存

## 4. 宝塔 Nginx 实际目录

这台服务器不是系统原生 `/etc/nginx/sites-available` 结构，而是宝塔自己的 Nginx 目录。

实际以这些路径为准：

- 主配置：`/www/server/nginx/conf/nginx.conf`
- 站点配置目录：`/www/server/panel/vhost/nginx`
- 当前正式站点配置：`/www/server/panel/vhost/nginx/offer360.conf`
- 证书目录：`/www/server/panel/vhost/cert`
- 当前站点证书目录：`/www/server/panel/vhost/cert/www.offer360.cn`

宝塔 Nginx 会自动加载：

```text
/www/server/panel/vhost/nginx/*.conf
```

所以后续新增站点，不需要自己维护 `sites-enabled` 软链接。

## 5. 当前 Nginx 生效逻辑

### 5.1 当前已生效站点

- `offer360.cn`
- `www.offer360.cn`

### 5.2 当前正式站点文件

```text
/www/server/panel/vhost/nginx/offer360.conf
```

### 5.3 生效方式

每次修改宝塔 Nginx 配置后，统一执行：

```bash
sudo /usr/bin/nginx -t
sudo /etc/init.d/nginx reload
```

不要跳过语法检查。

### 5.4 当前站点缓存要求

- `offer360.conf` 的 `location /` 必须直接反向代理到 `127.0.0.1:3000`
- `offer360.conf` 的 `location /` 与 `location ^~ /_next/static/` 必须显式关闭代理缓存
- 原因：宝塔全局 Nginx 可能通过公共 `proxy.conf` 默认开启 `proxy_cache`；如果对 Next.js 页面 HTML 或 `/_next/static` 资源做了代理缓存，公网入口可能继续返回旧版 HTML，导致页面继续引用已失效的 chunk
- 真实故障表现通常是：`127.0.0.1:3000` 直连正常，但正式域名跳转后页面布局错乱、样式异常、组件未正常加载，且 HTML 中引用的页面级 `/_next/static/chunks/app/...page-*.js` 与容器内当前版本不一致

## 6. HTTPS 证书与自动续签

### 6.1 当前证书来源

当前证书由 `certbot` 签发，证书原始目录：

```text
/etc/letsencrypt/live/offer360.cn
```

宝塔 Nginx 实际读取的证书目录：

```text
/www/server/panel/vhost/cert/www.offer360.cn
```

### 6.2 为什么需要同步

`certbot` 自动续签后，只会更新 `/etc/letsencrypt/live/...`。

但宝塔 Nginx 当前读取的是：

```text
/www/server/panel/vhost/cert/www.offer360.cn/fullchain.pem
/www/server/panel/vhost/cert/www.offer360.cn/privkey.pem
```

所以续签后必须把新证书同步到宝塔目录并 reload Nginx，否则线上仍可能继续使用旧证书。

### 6.3 当前续签策略

当前服务器已经启用：

- `certbot.timer`

并约定使用以下同步脚本：

```text
/usr/local/bin/sync-bt-cert.sh
```

建议部署 hook：

```text
/etc/letsencrypt/renewal-hooks/deploy/offer360-bt-sync.sh
```

hook 内容建议保持为：

```bash
#!/usr/bin/env bash
set -euo pipefail
/usr/local/bin/sync-bt-cert.sh offer360.cn www.offer360.cn
```

同步脚本源码已放入仓库：

```text
deploy/prod/scripts/sync-bt-cert.sh
```

当前服务器已实际安装：

- `/usr/local/bin/sync-bt-cert.sh`
- `/etc/letsencrypt/renewal-hooks/deploy/offer360-bt-sync.sh`

### 6.4 手动同步命令

如需人工执行：

```bash
sudo /usr/local/bin/sync-bt-cert.sh offer360.cn www.offer360.cn
```

## 8. 当前生产发布方式

当前采用离线发布，不依赖线上实时拉业务镜像。

发布核心文件：

- 业务离线包：`/opt/offer360/offer360-offline-20260517-140404.tar`
- 生产环境变量：`/opt/offer360/.env`
- Compose 文件：`/opt/offer360/deploy/prod/docker-compose.yml`

核心发布命令：

```bash
cd /opt/offer360/deploy/prod
APP_IMAGE_TAG=20260517-140404 \
IMAGE_ARCHIVE=/opt/offer360/offer360-offline-20260517-140404.tar \
ENV_FILE=/opt/offer360/.env \
bash scripts/deploy-release.sh
```

当前发布脚本已内置以下保护动作：

- 发布前仅清理 `web/api/wechat-pay-gateway` 旧容器与构建缓存
- 不删除 `mysql_data`、`redis_data`、`es_data` 等持久化卷
- 发布后自动抓取关键路由 HTML：`/`、`/resume-optimizer`、`/interview-transcript`
- 同时校验本地入口 `http://127.0.0.1:3000` 与公网入口 `https://www.offer360.cn` 这些关键路由中引用的 `/_next/static` CSS/JS 是否都能返回 `200`
- 同时校验公网 `robots.txt` 与 `sitemap.xml` 是否已经输出正式域名，且 sitemap 内是否已经包含服务详情页 URL
- 如果关键路由没有解析到 CSS，或任一路由的静态资源不可访问，发布直接判定失败
- 如果 `robots.txt` / `sitemap.xml` 仍出现 `localhost`、`127.0.0.1` 或 sitemap 缺少服务详情页 URL，发布也应直接判定失败

## 10. 排查顺序

### 10.1 页面打不开

先查：

```bash
curl -I http://offer360.cn
curl -I https://www.offer360.cn
docker ps
sudo /usr/bin/nginx -t
```

### 10.2 Nginx 代理失败

先查：

```bash
curl -fsS http://127.0.0.1:3000/healthz
curl -fsS http://127.0.0.1:4000/healthz
docker compose --env-file /opt/offer360/.env -f /opt/offer360/deploy/prod/docker-compose.yml ps
```

再查关键路由是否出现“本地入口正常、公网入口仍引用旧 chunk”：

```bash
curl -fsS http://127.0.0.1:3000/interview-transcript | grep -oE '/_next/static/[^"]+page-[^"]+\.js' | head
curl -fsS https://www.offer360.cn/interview-transcript | grep -oE '/_next/static/[^"]+page-[^"]+\.js' | head
```

如果 `127.0.0.1:3000` 与正式域名解析出的页面级 chunk 不一致，应优先排查：

- 宝塔 Nginx 站点配置是否仍命中代理缓存
- `offer360.conf` 是否已经同步到服务器
- `sudo /etc/init.d/nginx reload` 是否已执行

### 10.3 证书异常

先查：

```bash
systemctl status certbot.timer
ls -lah /etc/letsencrypt/live/offer360.cn
ls -lah /www/server/panel/vhost/cert/www.offer360.cn
```

### 10.4 结构同步失败

先查：

- `/opt/offer360/.env` 是否包含 `DATABASE_URL`
- `/opt/offer360/infra/sql/schema.sql` 是否存在
- `mysql` 容器是否健康

## 11. 上线前最小检查清单

每次新站上线前至少确认：

1. 域名解析已生效
2. 证书目录存在且证书匹配域名
3. Docker 项目只绑定 `127.0.0.1:<端口>`
4. 宝塔 Nginx 配置文件已放到 `/www/server/panel/vhost/nginx`
5. 对 Next.js 站点，确认 `location /` 与 `location ^~ /_next/static/` 已关闭代理缓存
6. `sudo /usr/bin/nginx -t` 成功
7. `sudo /etc/init.d/nginx reload` 已执行
8. `curl -I 域名` 返回正常
9. 容器健康检查通过
10. `http://127.0.0.1:3000` 与正式域名的关键路由 `/_next/static` 资源验收一致
11. `https://www.offer360.cn/robots.txt` 与 `https://www.offer360.cn/sitemap.xml` 已通过正式域名 SEO 入口验收
